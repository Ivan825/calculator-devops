1. Overview

The application is a Calculator REST API written in Java 21 with Spring Boot 3.5 and built with Maven. It exposes add, subtract, multiply and divide under /api/v1, and a Spring Actuator health probe at /actuator/health. Operands are handled as BigDecimal, so decimal arithmetic is exact (0.1 + 0.2 = 0.3). Every client error (division by zero, a missing or non-numeric parameter, an out-of-range operand) returns HTTP 400 with the same JSON body: timestamp, status, error, message, path.

Around the application sits a pipeline that needs no manual steps. A push to main on GitHub is picked up by Jenkins, which builds, tests and packages the code, builds a Docker image tagged with the build number, pushes it to Docker Hub and redeploys the Docker Compose stack. Jenkins then checks the stack's health and emails the result.

Deploydocker compose up -d --no-build --remove-orphans --wait rolls the stack to the new tag and blocks until every container is healthy. A smoke test then calls /actuator/health and /api/v1/add through Nginx. If deployment fails, docker compose ps and the container logs are printed.20 s
PostPrunes all but the last 5 numbered image tags and dangling layers, then emailext emails the result (SUCCESS or FAILURE) with links to the console and test report. Email goes through Gmail SMTP using credentials stored in Jenkins.6.2 s

Re-runnable and idempotent. disableConcurrentBuilds() stops two deploys from racing. Compose recreates only the containers whose image or configuration changed, so re-running a build leaves a healthy deployment as it is; a second up with the same tag recreated nothing.

Containerization and deployment

  • Dockerfile (multi-stage). The build stage (maven:3.9.11-eclipse-temurin-21) copies pom.xml and runs dependency:go-offline before copying src/, so the dependency layer stays cached until the POM changes. The runtime stage (eclipse-temurin:21-jre-alpine) copies only the JAR, runs as the non-root user spring, declares EXPOSE 8080 and has a HEALTHCHECK. A .dockerignore keeps target/, .git/ and IDE files out of the build context.
  • docker-compose.yml. Two calculator replicas (health check on /actuator/health, restart: unless-stopped, environment variables SERVER_PORT, APP_VERSION, JAVA_OPTS) sit on an internal backend network. An nginx reverse proxy, which waits for the API to be healthy and has its own health check, is the only service on the frontend network and publishes host port 8081. One docker compose up starts the whole stack.
  • Git workflow. Development happened in steps on feature/calculator-api, feature/containerization and feature/jenkins-pipeline, each merged into main with a merge commit. A .gitignore covers Maven, IDE files and secrets.

4. Challenges faced

  • Nginx sent every request to one replica. My first configuration used proxy_pass with a variable and Docker's DNS resolver. Nginx resolved the service name once per DNS TTL and kept using the first address, so the X-Upstream-Server header never changed. I switched to an upstream block with a shared-memory zone and server calculator:8080 resolve (available in open-source Nginx 1.27.3 and later). Requests now alternate between both replicas, and Nginx picks up new IPs when Compose recreates the containers.
  • Port conflict with Jenkins. Jenkins already listens on 8080, so the stack publishes Nginx on 8081, set in .env.
  • Jenkins runs with a minimal PATH. Homebrew's Jenkins runs as a macOS launch agent whose PATH doesn't include Docker Desktop's /usr/local/bin. The Jenkinsfile prepends it in its environment block, and the Maven wrapper avoids needing a Jenkins-managed Maven install.
  • No public URL for a webhook. Jenkins listens only on localhost, so GitHub can't deliver a webhook to it without a tunnel such as ngrok. The job polls GitHub every minute instead, which the brief accepts. The githubPush() trigger is still declared, so adding a tunnel and a webhook would make builds start instantly.
  • Credential ID rejected. Jenkins reported "Unacceptable characters" for dockerhub-credentials. A pasted invisible leading space was the cause; retyping the ID fixed it.
  • Number formatting and abuse. BigDecimal.stripTrailingZeros() serialised 10 as 1E+1, which spring.jackson.generator.write-bigdecimal-as-plain=true fixed. Inputs like 1e999999999 could force huge computations, so operands are limited to 50 significant digits and an exponent within ±1000, with a 400 response outside that.
